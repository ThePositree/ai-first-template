# Next Release Checklist

Use this checklist when preparing the next public release notes.

- Describe AI-first as Markdown-first project memory for AI-assisted repositories.
- Emphasize passive defaults: no daemon, hosted service, hidden database, global CLI, repeated runner command, or target-repository `node_modules`.
- Explain progressive disclosure: agents start with compact local context and load detailed guidance only when the request requires it.
- Treat playbooks as detailed workflow guidance, not startup context.
- Describe tracker support as migration between task sources of truth, not automatic mirroring.
- Keep source project Markdown and installable envelope Markdown separate in release notes.
