## Briefing Notes

When the owner asks to migrate AI-first task state into GitHub, run a fresh briefing first unless the owner explicitly says to reuse an existing recorded policy. Record the approved policy here. The briefing should cover surfaces, entity placement, scope, labels or fields, Projects, Wiki, Discussions, relationships, existing GitHub data, sync mode, source of truth, conflict handling, approvals, visibility, and dry-run preference.

This file is a policy record, not permission to run future GitHub writes without owner confirmation. Show the planned GitHub entities before apply and wait for explicit approval.

If Projects, Wiki, Discussions, or another selected surface is disabled or inaccessible, ask whether the owner wants it enabled. If you cannot enable it yourself, explain exactly what the owner must do and wait before falling back.

Use repository-native labels or fields rather than AI-first-branded tracker metadata. Do not mirror task state by default.

Do not add GitHub-only relationship links to normal `.ai-first` memory files unless the owner explicitly approves GitHub as a source of truth.
